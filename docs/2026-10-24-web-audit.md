## Eng muhim topilmalar

### A01 · P1 · Server chat fayllariga muddatsiz havola beradi

Supabase’da ishlab turgan `cloudinary-media` v32 funksiyasining `signedUrl` amali hujjatlar uchun 900 soniyalik URL yaratadi. `chat` va ayrim boshqa media scope’lar uchun esa `signedAuthenticatedDeliveryUrl()` qaytaradi: `expiresAt: null`, `expirationEnforced: false`.

Bunday havola dastlab ruxsatli foydalanuvchiga beriladi, lekin keyinchalik uni bilgan shaxs havoladan ilova sessiyasidan tashqarida ham foydalanishi mumkin. Ilovadan chiqish yoki RLS ruxsatini bekor qilish CDN imzosini avtomatik bekor qilmaydi. Bu boshqa foydalanuvchining fayli ochib ko‘rilgani yoki ma’lumot o‘g‘irlangani haqida dalil emas; xavf serverning hozirgi yetkazib berish usulidan kelib chiqadi.

Lokal kod barcha scope uchun 15 daqiqalik URL yaratishga o‘zgartirilgan, lekin shu o‘zgarish serverdagi v32 bilan mos emas.

- Dalil: [serverdan o‘qilgan nusxa](C:/Users/Intel/Desktop/driverweb/output/web-audit-remote-cloudinary-index.ts:305), [lokal variant](C:/Users/Intel/Desktop/driverweb/supabase/functions/cloudinary-media/index.ts:294).
- Tuzatish: xususiy media uchun qisqa muddatli URL yoki har ochishda ruxsatni tekshiradigan proxy’ni serverda ham joriy qilish. Oldin chiqarilgan muddatsiz URL’larni alohida bekor qilish rejasi kerak; yangi URL’larning muddatli bo‘lishi eski imzolarni bekor qilmaydi.
- Mexanizm: [Cloudinary access-control hujjati](https://cloudinary.com/documentation/control_access_to_media).

### A03 · P1 · Lokal Vite 8.3.0 uchun Windows xavfsizlik ogohlantirishi bor

To‘liq `npm audit` Vite uchun yuqori darajadagi `launch-editor` ogohlantirishini ko‘rsatdi. O‘rnatilgan Vite — 8.3.0; rasmiy advisory’da 8.3.3 tuzatilgan versiya sifatida ko‘rsatilgan. Windows’da maxsus tuzilgan editor fayl argumenti boshqa escaping muammosi bilan birga OS buyruq bajarilishiga olib kelishi mumkin. Auditda ekspluatatsiya yuborilmadi.

Default dev konfiguratsiyada `host: true`, `allowedHosts: true`. Hozir tekshirilgan server buyruqda `127.0.0.1` bilan ishga tushirilgan, shuning uchun uni internetga ochiq deb baholamadim. Xavf dev server/editor yo‘liga tegishli; statik production build’da Vite dev server ishlamaydi.

- Tuzatish: Vite’ni tuzatilgan versiyaga yangilash, lockfile’ni yangilab tekshirish; default dev host’ni loopback bilan cheklash va `allowedHosts: true` o‘rniga kerakli hostlarni ko‘rsatish.

## Xavfsizlik bo‘yicha ijobiy dalillar

- Public schema’dagi 53 ta oddiy jadvalning barchasida RLS yoqilgan. Tekshirilgan barcha exposed view’lar `security_invoker=true`.
- 5 ta Storage bucket’ning barchasi private: broker-originals, load-documents, profile-media, chat-media, driver-earnings.
- Anonim REST so‘rovlarida profiles, loads, document_versions, media_assets, driver_earnings va gmail_connections ma’lumotlari 401/42501 bilan rad etildi. dispatcher_preferences 200 va bo‘sh massiv qaytardi: public SELECT grant bor, lekin RLS anonimga qator bermadi.
- Authsiz document-content so‘rovi, create-member va parse-load-document POST so‘rovlari 401 qaytardi. GET’dagi 405 faqat method cheklovi bo‘lib, auth buzilgani sifatida baholanmadi.
- Gateway JWT tekshiruvi o‘chiq 8 deployed function entry’si ko‘rildi: ular ichida user auth, worker secret yoki imzolangan call capability tekshiruvlari bor. `verify_jwt=false`ning o‘zi auth yo‘qligini anglatmaydi.
- SECDEF funksiyalarda search_path o‘rnatilmagan holat topilmadi. 113 ta authenticated-callable SECDEF advisor ogohlantirishi avtomatik zaiflik deb belgilanmadi: ko‘pi role/tenant tekshiruvchi command RPC’lar. SQL testlaridagi tenant, permission, idempotency va concurrent ownership/assignment holatlari o‘tdi.
- Anonimga EXECUTE granti qolgan `ensure_vehicle_assignment_tenant()` — `RETURNS trigger`. Bu oddiy RPC sifatida chaqiriladigan biznes API emas. Grantni bekor qilish foydali, lekin uni tasdiqlangan anonim data-write zaifligi deb baholamadim.
- 13 ta “RLS enabled, no policy” INFO orasida xizmatga yopiq queue/private jadvallar bor; no-policy odatda client kirishini rad etadi. Ularni shunchaki “ishlatish uchun” ochish tavsiya qilinmaydi.
- Lokal env’dagi 12 ta server qiymati client build matnlari bilan solishtirildi: mos kelgan secret topilmadi. Haqiqiy `.env` fayllar Git’ga kuzatilmaydi va Vercel upload’dan chiqarilgan. Tracked manbalarda service-role JWT topilmadi. Private-key marker topilmalari validator/test kodlari bo‘lib chiqdi. Bu butun Git tarixining secret scan’i emas.
- Frontendda `dangerouslySetInnerHTML`, `eval`, `new Function` va to‘g‘ridan-to‘g‘ri `innerHTML=` sink’lari topilmadi. PDF parser’da `isEvalSupported: false`; CSV eksportida formula-prefiks himoyasi mavjud.
- PDF cache’dan qayta ochishda ham metadata ruxsati yangidan tekshirilishi va ruxsat bekor qilinganda eski PDF ko‘rinmasligi testlardan o‘tdi.
